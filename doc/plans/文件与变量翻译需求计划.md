# variable-translator - VSCode 插件

> **当前版本**：v0.1.1 | **状态**：已完成 ✅

## 功能概述

一款 VSCode 插件，自动检测并翻译任意非英文字符为英文（中文、日文、韩文等），支持文件路径翻译和选中文本翻译。

### 核心能力（v0.1.1）

- 文件路径翻译：新建/重命名文件、文件夹时自动检测非英文并翻译
- 选中文本翻译（Alt+Shift+T）与翻译并复制（Alt+Shift+C）
- 8 种命名格式转换 + originalValue 原始值复制
- 7 个翻译服务（拼音零配置兜底），优先级降级链 + 超时保护
- 撤回翻译（Alt+Shift+Z 全局生效，Ctrl+Z 在非文本输入区条件生效；1 分钟内有效，自动清理翻译创建的空目录）
- 多格式剪贴板复制（兼容 Windows 剪贴板历史 Win+V）
- 文件名字符净化（如 `user's` → `users`），确保结果符合文件命名规范

## 功能1：新建/重命名文件时翻译路径

### 使用场景
用户在 VSCode 资源管理器中右键新建文件或文件夹，或重命名现有文件/文件夹，输入包含任意非英文字符（中日韩等）的路径，插件自动检测语言并翻译为英文。

### 操作流程
```
新建：右键新建文件/文件夹 → 输入路径 → 回车 → 选择翻译格式 → 回车 → 自动翻译创建
重命名：右键重命名文件/文件夹 → 输入新名称 → 回车 → 选择翻译格式 → 回车 → 自动翻译
```

### 示例
```
输入：用户名称/测试文件/测试.test.js

格式选择：
- camelCase:      userName/testFile/test.test.js
- PascalCase:     UserName/TestFile/Test.test.js
- snake_case:     user_name/test_file/test.test.js
- CONSTANT_CASE:  USER_NAME/TEST_FILE/TEST.test.js
- param-case:     user-name/test-file/test.test.js
- Header-Case:    User-Name/Test-File/Test.test.js
```

### 取消操作行为
```
新建文件：按 ESC 取消 → 保留原文件/文件夹（不删除）
重命名文件：按 ESC 取消 → 保留原文件/文件夹（不删除）
```

### 撤回功能
```
按 Alt+Shift+Z（或在资源管理器等非文本输入区按 Ctrl+Z）→ 删除翻译后的文件/目录 → 自动清理空目录 → 关闭该文件的编辑器窗口
```

**撤回规则**：
- 撤回操作会直接删除翻译后的文件，而不是恢复到原始非英文路径
- 仅清理翻译时创建的目录：通过对比翻译前后的路径判断，相同前缀段（如 `src/`）属于用户原有目录，绝不清理
- 工作区归属判断使用 `path.relative`（而非大小写敏感的 `startsWith`），规避 Windows 盘符大小写（`d:` vs `D:`）导致清理逻辑被跳过
- 只关闭被删除文件的编辑器窗口，不会关闭其他已打开的文件
- **1分钟内可撤回**，1分钟后自动清空撤回缓存
- `Ctrl+Z` 通过 context key `variableTranslator.canUndoFile`（when 条件 `!inputFocus`）接管：编辑器内保持 VSCode 原生文字撤销；撤回完成后到 1 分钟窗口结束前仍保持接管（重复按下仅提示无可撤回记录），避免落到原生文件撤销栈上触发“创建原始文件”失效记录的报错

> 例如：在 `src/` 下输入 `你好/世界/美好.test.js`，翻译为 `src/hello/world/beautiful.test.js` 后撤回，会删除 `hello/world/` 和 `hello/`，但 `src/` 无论是否为空都会保留。

### 文件名冲突处理
```
场景：目标文件已存在（如 test.test.js 已存在）
处理：自动添加后缀（如 test_1.test.js）并提示用户
```

### 文件名字符净化
> **仅在新建/重命名文件与文件夹时生效**，不影响「选中文本翻译」等文件内容的翻译结果。

翻译接口返回的英文结果可能包含不符合文件命名规范的字符（如 `'s`、标点、括号、斜杠等），生成文件名前统一净化：

| 规则 | 处理方式 | 示例 |
|------|----------|------|
| 词内撇号（`'` `’` `＇` `` ` ``） | 直接删除，保留单词完整性 | `user's` → `users`、`don't` → `dont` |
| 其余所有非字母数字字符 | 统一视作分隔符切分 | `hello, world!` → `hello` `world` |
| 数字 | 保留 | `version 2` → `version` `2` |
| 净化后无有效单词 | 回退使用原始文件名，避免空或非法文件名 | `***` → 原名 |

```
输入：用户's文件
翻译接口返回：user's file
净化 + camelCase：usersFile（不会出现非法字符 ' ）
```

### 翻译失败降级
```
场景：翻译API调用失败（网络错误、配额用完等）
处理：按优先级降级到下一个服务 → 所有服务失败 → 自动降级为拼音翻译
全局翻译超时（10秒）→ 自动降级为拼音转换
```

### 配置项
此功能可在设置中开启/关闭：
```json
{
  "variableTranslator.enableFileTranslation": true
}
```

## 剪贴板功能设计

### 需求背景
用户希望翻译后能快速获取多种命名格式的结果，方便在不同场景下使用。

### 配置项说明
```json
{
  "variableTranslator.copyToClipboard": {
    "type": "boolean",
    "default": false,
    "description": "翻译完成后自动将结果复制到剪贴板（需配合 clipboardFormats 使用）"
  },
  "variableTranslator.clipboardFormats": {
    "type": "array",
    "items": {
      "type": "string",
      "enum": [
        "camelCase",
        "originalValue",
        "PascalCase",
        "no case",
        "snake_case",
        "CONSTANT_CASE",
        "param-case",
        "Header-Case",
        "Capital Case"
      ]
    },
    "default": [],
    "description": "复制到剪贴板的命名格式（支持多选，按顺序逐条写入剪贴板历史）"
  }
}
```

### 配置逻辑
| copyToClipboard | clipboardFormats | 行为 |
|-----------------|------------------|------|
| false | 任意 | 只翻译，不复制 |
| true | 有值 | 翻译后复制：用户选择的格式排第一 + clipboardFormats 其余格式 |
| true | 空数组 | 翻译后只复制用户选择的单个格式 |

> 上表适用于「翻译选中文本」（Alt+Shift+T，替换场景）。「翻译并复制」（Alt+Shift+C）与文件/路径翻译始终会复制：`copyToClipboard=false` 或 `clipboardFormats` 为空时，兜底复制用户选择的单个格式。

### 场景1：选中文本翻译

#### 快捷键：Alt+Shift+T（翻译并替换）
```
1. 选中文本 → 按 Alt+Shift+T
2. 弹出格式选择框 → 用户选择格式
3. 翻译并替换选中文本
4. 如果 clipboardFormats 有值：
   - 重排 clipboardFormats（用户选择的排第一）
   - 按重排后的格式依次复制到剪贴板
```

#### 快捷键：Alt+Shift+C（翻译并复制，不替换）
```
1. 选中文本 → 按 Alt+Shift+C
2. 弹出格式选择框 → 用户选择格式
3. 翻译（不替换原文）
4. 复制到剪贴板（此命令核心即为复制，始终会复制）：
   - copyToClipboard=true 且 clipboardFormats 有值：重排后依次复制
   - 其余情况（copyToClipboard=false 或 clipboardFormats 为空）：只复制用户选择的单个格式
```

#### 剪贴板写入示例
```
选中：用户名称
配置：["camelCase", "snake_case", "CONSTANT_CASE"]
用户选择格式：snake_case

执行 Alt+Shift+C 后：
剪贴板顺序重排：["snake_case", "camelCase", "CONSTANT_CASE"]（用户选择的排第一）
- 剪贴板历史第1条：user_name
- 剪贴板历史第2条：userName
- 剪贴板历史第3条：USER_NAME
- 当前剪贴板：USER_NAME（最后写入的）
```

#### 剪贴板顺序重排规则
```typescript
// 用户选择的格式排到第一，其余保持原序
function reorderFormats(formats: string[], selected: string): string[] {
  const rest = formats.filter(f => f !== selected);
  return [selected, ...rest];
}
```

### 场景2：文件/文件夹翻译

#### 获取复制内容的规则
```
输入：你好/世界/美好.test.js
翻译：hello/world/beautiful.test.js
复制内容：beautiful（最后一个目录名/文件名的翻译，不含扩展名）

输入：美好.test.js
翻译：beautiful.test.js
复制内容：beautiful

输入：.测试
翻译：.test
复制内容：test
```

#### 文件夹特殊处理
```
输入：你好/世界/美好/
翻译：hello/world/beautiful/
复制内容：beautiful（最后一个目录名）
```

#### 文件翻译的多格式剪贴板逻辑
```
输入：美好.test.js
配置：["camelCase", "snake_case", "CONSTANT_CASE"]
用户选择格式：snake_case

步骤：
1. 翻译文件名"美好" → "beautiful"
2. 用用户选择的格式转换：beautiful（snake_case）
3. 重命名文件：beautiful.test.js
4. 复制到剪贴板（重排后）：
   - beautiful（snake_case，用户选择的排第一）
   - beautiful（camelCase）
   - BEAUTIFUL（CONSTANT_CASE）

注意：多个格式是同一英文词的不同命名风格
```

> **复用文本翻译剪贴板逻辑**：文件/路径翻译的复制与「翻译并复制」（Alt+Shift+C）完全一致，统一走 `copyTranslationToClipboard`：
> - `copyToClipboard=true` 且 `clipboardFormats` 有值：按重排顺序依次写入剪贴板历史（遵循 `variableTranslator.clipboardFormats`）
> - 其余情况（`copyToClipboard=false` 或 `clipboardFormats` 为空）：兜底复制用户选择的单个格式（`lastTranslatedPart`）
> - `originalValue` 复制的是该段的原始非英文文本（如 `美好`）
>
> **写入时机**：多条剪贴板写入必须在「打开翻译后的文件之前」完成。打开新编辑器（`showTextDocument`）会引起窗口焦点抖动，导致 Windows 剪贴板历史服务丢弃快速连续写入中的中间项（表现为「只剩最后一条」）。因此文件翻译流程为：关闭原编辑器 → 逐条写入剪贴板 → **最后**再打开翻译后的文件，确保剪贴板历史逐条完整记录。

### 剪贴板技术要点

| 功能 | API | 说明 |
|------|-----|------|
| 写入剪贴板 | `vscode.env.clipboard.writeText(text)` | 每次调用会覆盖当前剪贴板，但剪贴板历史工具可记录 |

```typescript
// 逐条写入剪贴板（利用剪贴板历史工具记录）
for (const format of clipboardFormats) {
  const result = convertNaming(text, format);
  await vscode.env.clipboard.writeText(result);
}
// 最终保留最后一个格式在剪贴板
```

```
多条剪贴板写入依赖系统剪贴板历史工具：
- Windows: Win+V（需手动开启）
- macOS: 需第三方工具（如 Paste）
- Linux: 需第三方工具

用户无需配置，插件逐条写入即可
```

## 翻译服务支持

### 服务列表
| 服务 | 认证方式 | 费用 | 说明 |
|------|----------|------|------|
| 拼音（copilot）| 零配置 | 免费 | 默认服务，降级方案，支持中日韩字符拼音转换 |
| ChatGPT / OpenAI | API Key | 按量付费 | 支持自定义 baseUrl/model，兼容第三方 API |
| 谷歌翻译 | API Key | 按量付费 | 官方 Cloud Translation API，未配置 Key 时在降级链路中跳过 |
| Bing / Azure Translator | API Key | 按量付费 | 需要 Azure 账号，支持自定义区域 |
| DeepLX | 本地部署 | 免费 | 自动健康检查（60 秒缓存），支持自定义服务地址 |
| 百度翻译 | APP_ID + Key | 按量付费 | 需要百度翻译开放平台账号 |
| 腾讯翻译君 | SecretId + SecretKey | 按量付费 | 支持自定义区域（默认 ap-guangzhou） |

### 超时与降级
- 所有翻译服务统一 10 秒请求超时（共享 `fetchWithTimeout` 工具函数）
- 全局翻译超时保护（10 秒，`Promise.race`），超时自动降级
- 按 `servicePriority` 顺序降级，所有服务失败后兜底拼音转换（null 检查 + try/catch，保证永不崩溃）
- 拼音服务支持中文、日文（平假名/片假名）、韩文（音节/字母）

### API 获取方式
| 服务 | 获取地址 | 说明 |
|------|----------|------|

| Google 翻译 | [console.cloud.google.com](https://console.cloud.google.com/) | 启用 Cloud Translation API 并创建 API Key |
| 百度翻译 | [fanyi-api.baidu.com](https://fanyi-api.baidu.com/) | 开通通用翻译 API |
| 腾讯翻译君 | [console.cloud.tencent.com/cam/capi](https://console.cloud.tencent.com/cam/capi) | 获取 SecretId/SecretKey |
| Bing/Azure | [portal.azure.com](https://portal.azure.com/) | 创建 Translator 资源 |

## 配置项

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `variableTranslator.enableFileTranslation` | boolean | true | 是否启用文件路径自动翻译 |
| `variableTranslator.translationService` | string | copilot | 当前翻译服务（copilot 即拼音，零配置） |
| `variableTranslator.services` | object | {} | 各翻译服务的认证配置 |

### services 子项

```json
{
  "variableTranslator.services": {
    "openai": {
      "apiKey": "",
      "baseUrl": "留空使用官方地址，可配置第三方兼容接口",
      "model": "留空使用默认模型 gpt-4o-mini"
    },
    "google": { "apiKey": "" },
    "baidu": { "appId": "", "secretKey": "" },
    "tencent": { "secretId": "", "secretKey": "", "region": "ap-guangzhou" },
    "bing": { "apiKey": "", "region": "global" },
    "deeplx": { "baseUrl": "留空使用默认 http://localhost:1188" }
  }
}
```

### 配置值运行时验证
- `getServicePriority`：过滤无效的服务类型
- `getClipboardFormats`：过滤无效的格式值
- 所有配置在调用时实时读取（`vscode.workspace.getConfiguration`），修改后无需重启即时生效

### 使用示例
```json
{
  "variableTranslator.copyToClipboard": true,
  "variableTranslator.clipboardFormats": [
    "camelCase",
    "originalValue",
    "snake_case",
    "CONSTANT_CASE"
  ]
}
```

**效果**：翻译"用户名称"后，剪贴板历史中会依次包含：
- `userName`（camelCase）
- `用户名称`（原始值）
- `user_name`（snake_case）
- `USER_NAME`（CONSTANT_CASE）

最终剪贴板保留最后一个格式（用户选择的格式会排到第一位）

## 技术实现要点

### VSCode API 使用
| 功能 | API | 说明 |
|------|-----|------|
| 文件创建监听 | `vscode.workspace.onDidCreateFiles` | 监听文件创建事件 |

### 核心流程
```
1. 文件路径翻译流程：
   用户新建文件 → onDidCreateFiles事件 → 检测非英文 → 选择格式 → 翻译 → 重命名 → 关闭原编辑器 → 复制到剪贴板 → 打开翻译后的文件

2. 选中文本翻译流程：
   用户选中文本 → Alt+Shift+T → 检测非英文 → 选择格式 → 翻译 → 替换 → 复制到剪贴板

3. 翻译并复制流程：
   用户选中文本 → Alt+Shift+C → 检测非英文 → 选择格式 → 翻译 → 复制到剪贴板（不替换）

4. 撤回流程：
   用户按Alt+Shift+Z（或窗口期内非文本输入区按Ctrl+Z） → 查找撤回记录 → 确认删除 → 关闭窗口 → 删除文件 → 清理翻译创建的空目录

5. 翻译服务降级流程：
   按优先级顺序尝试翻译服务 → 失败 → 降级到下一个服务 → 所有服务失败 → 降级到拼音
```

## 错误处理

| 场景 | 处理方式 |
|------|----------|
| 翻译API调用失败 | 降级为拼音翻译 |
| 翻译超时（10秒） | 自动降级，防止卡死 |
| 目标文件已存在 | 自动添加后缀（如 test_1.test.js）并提示 |
| 撤回超时（超过1分钟）或已撤回 | 提示“没有可撤回的翻译记录（已撤回或超过 1 分钟有效期）” |
| 未配置API Key | 切换时提示需要配置 |
| AbortError 检测 | 兼容 DOMException 与 Node.js Error.code |
| 错误消息提取 | 安全提取，防止显示 `[object Object]` |
| 纯英文文本 | 显示信息提示（无需翻译） |
